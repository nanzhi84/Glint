# 划词浮窗落点精确改进实验 (Cursor Bottom-Right Placement Experiment)

本实验针对 `Glint` 划词气泡落点漂移、无法精确落在光标右下角的问题，基于本机 `~/.config/glint/glint.log` 真实运行日志与双屏环境构造可复现基准测试。

## 1. 实验脚本与运行方式

- 实验源码：[run_experiment.swift](run_experiment.swift)
- 隔离运行命令：
  ```bash
  yoryon-harness run cursor-placement-exp -- swift experiments/cursor-placement/run_experiment.swift
  ```

## 2. 实验发现与根因量化

### 2.1 真实日志统计（`~/.config/glint/glint.log` 尾部 250KB）

- AX 返回非空 `bounds` 共 **248 次**，其中：
  - 方法 1（`kAXBoundsForRange`）返回 `(0,0,0,0)` 空矩形而回退至方法 2/3 共 **254 次**；
  - 落入方法 3（`AXFrame` 整个焦点元素外框）共 **51 次**；
  - 被 `plausibleSelectionBounds` 拦截判为不可信共 **62 次**（仍有大量块级容器外框因高度未超阈值而漏检通过）。
- AX 返回 `bounds=nil`（终端、Claude Code 等走剪贴板路径）共 **206 次**。

### 2.3 双显示器交界处跳屏复现

在本机双屏环境（左侧外接屏 `screen[1]: x = -2560..0`，右侧主屏 `screen[0]: x = 0..1728`）下：
- 当用户在 `screen[1]` 右侧（如 `x = -120`）划词并点开 `460px` 宽的解释浮窗时，展开矩形的 `midX = +110 > 0` 落入 `screen[0]`，旧版 `screenFor(rect)` 按 `midX` 查屏会将浮窗错误夹紧并跳变到 `screen[0]`。
- 改为按光标点 `pt` 与浮窗左上角锚点 `topLeft` 查屏后，浮窗始终稳定留在当前操作的显示器内。
